# Ranked refactor candidates

Locations refer to the review base named in inventory.md. Effort estimates are
relative engineering effort, not a claim about completed work or scheduling.

| Rank / candidate | Current behavior and concrete cost | Proposal and alternatives | Benefit, risks and effort | Decision |
| --- | --- | --- | --- | --- |
| 1. Buffered output | `invoke_native_active native_log` appends one line to `state.output`; every append walks/copies the preceding list. | Prepend into explicitly named `output_reversed`, reverse once in `run_command_with_host`. Alternative: a difference-list function or queue. | Removes repeated prefix copying without new types/dependencies. Must preserve blank lines, nested calls, aliases, exit and failed-run behavior. Small. | Implement and measure; simple reverse has less machinery than a queue. |
| 2. Dense array construction | `allocate_array` creates unique sequential keys, then `allocate_aggregate` runs `put_entry` over all earlier keys for every member. JSON, argv and directory responses reuse it. | Separate `allocate_array` and `allocate_object`, sharing only identity/storage insertion. Dense arrays install the generated unique keys directly; objects retain duplicate replacement. Alternative: indexed persistent storage everywhere. | Removes quadratic duplicate searching from dense construction. Preserve member order, nested identities, holes after growth, and object last-value/first-position behavior. Small. | Implement and measure; no property representation change. |
| 3. Dead environment model | `Environment`, `lookup_variable`, `set_variable`, `define_variable` describe the old direct-value environment but have no runtime callers. | Remove these private definitions. Alternative: annotate them as historical. | Removes a misleading second model; no exported API change. Tiny. | Worth removing as a separate coherent cleanup commit after the full baseline. |
| 4. Source module boundaries | One file owns pure syntax, state and operating-system imports. Refusal harnesses currently symlink just this file. | Future dependency order: model → syntax; pure paths/JSON grammar; storage and JSON conversion; evaluation plus host contract; concrete file host. Retain Fieldmouse as public facade. | Real reasoning benefit, but an all-at-once split changes visibility and isolated refusal builds. Medium. | Defer broad split; first preserve and test these seams. File length alone is insufficient. |
| 5. Indexed cell/identity stores | `read_binding` scans names then all retained cells; writes copy prefixes. Aggregate and function lookup also scan lifetime-growing lists. | Benchmark a persistent ordered map for identities, retaining name-to-cell semantics; separately compare lexical frames or resolved references. | May improve lookup scaling, but must preserve captured cell sharing and declaration shadowing. Container and Number comparison costs need measurement. Medium/large. | Separate measured job. No speed claim from inspection alone. |
| 6. Object/array property stores | `put_entry`, `read_property`, `serialize_array`, `array_text_values` scan property lists. Dense serialization repeatedly looks up each key. | Compare an ordered object representation and dedicated sparse array representation; retain array length and holes. | Could reduce quadratic scans. Sorting a generic map would change current JSON key order; numeric and text keys need exact tests. Medium. | Defer; dense construction is the safe subset now. |
| 7. Retained storage and captures | Runtime retains every cell, aggregate and closure until the run ends. Closures capture all visible binding entries. | Measure retained heap with repeated calls; then consider free-variable capture and reachability reclamation. Alternative: document small-helper lifetime. | Important for long-running work; unsound reclamation breaks escaping closures, self recursion and cycles. Large. | Document weakness; do not add a collector without a root/lifetime design. |
| 8. Source positions and recovery | `token` carries spelling only; `Either Text` errors have no filename/span; first error aborts. | Add located tokens and structured diagnostics while preserving stable message categories. Recovery only for a future editor use case. | Large usability gain. Public token API and negative diagnostics change; source offsets must specify Unicode units. Medium. | Separate job; changing observable diagnostics needs an explicit contract. |
| 9. Indexed host responses | `Host` permits any response constructor; evaluator rejects mismatches. Pure operations share the native-function enumeration with effects. | Consider request-indexed response type or a checked adapter layer while retaining legacy Host compatibility. Alternative: keep closed choices and tests. | Could exclude wrong responses statically, but public injected-host type would change. Medium. | Keep current boundary; useful and already exercised. No stringly extensible registry. |
| 10. JSON deduplication/fusion | Source and JSON scanners overlap but accept different numbers, escapes and literals; JSON tree is allocated before runtime import. | Only share proven identical helpers; compare parse-and-allocate against current pure parse if peak memory matters. | Fusion removes intermediate allocation but couples syntax failure to Runtime construction. Reusing dialect parser accepts invalid JSON. Medium. | Reject wholesale scanner unification. Defer fusion pending measurements. |
| 11. Control representation | `returned` and `stopped` are optional fields; evaluation is mutually recursive and many branches check stop state. | Future explicit completion choice and central state sequencing. Alternative: keep current clear branch cases. | May reduce missed-stop paths, but nested return/exit/error ordering is observable and needs broader characterization. Medium/large. | Defer; do not disguise control-flow redesign as a file split. |
| 12. Parser abstraction/operator indexing | Precedence tiers search small fixed operator lists; function/block parsers duplicate a short loop. | Shared terminator-aware block helper or direct operator dispatch. Alternative: Pratt parser / parser library. | Little likely gain at 15 operators. Historic helper-recursion regression and diagnostic distinctions add risk. Small/medium. | Reject new parser framework; retain current precedence parser. |
| 13. Multiple grammars | Only the dialect parser exists; shared AST contains potentially reusable operations. | Add an explicitly selected conventional-JS frontend later, lowering only genuinely common semantics. | Preserves original goal. Token rewriting cannot supply hoisting, receivers or coercion. Large. | Out of this refactor; do not promise compatibility from the shared AST. |
| 14. VM/runtime replacement | Direct interpreter is coherent for small helpers. | Bytecode VM, MuJS restoration, another implementation language or large library upgrade. | No workload evidence offsets migration and compatibility costs. Large. | Reject. |

Numeric review found a concrete existing edge: `!!(0 / 0)` evaluates to true
because `truthy` tests only nonzero, unlike JavaScript NaN falsiness. Undefined
numeric conversion errors and strict/loose comparisons also follow the current
limited dialect. Record and propose any semantic correction separately; do not
change it under a behavior-preserving refactor.
